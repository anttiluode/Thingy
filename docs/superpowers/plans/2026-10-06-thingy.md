# Thingy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the inspectable self-ping machine described in the attached discussion, with actual training and causal receipts.

**Architecture:** A small NumPy neural controller emits named sparse packets into a delta-rule fast operator. Episode facts, unfinished work, private state, and public decoding are separate and can be restored independently. A local HTTP explorer operates the exact same engine.

**Tech Stack:** Python 3.10+, NumPy, standard-library unittest and HTTP server, plain HTML/CSS/JavaScript.

**Spec:** `docs/superpowers/specs/2026-10-06-thingy-design.md`

## Global Constraints

- CPU-scale research instrument, Python 3.10+ and NumPy only.
- 16 named objects and four arbitrary relations; existing MIT license retained.
- Training and hard sparse evaluation are distinct; no runtime target access.
- Independent episode RNG streams and frozen weights for reported evaluation.
- Four controller ablations, never presented as transformer comparisons.
- Model/receipts in JSON; loopback local explorer; explicit package discovery.

## Review Focus

- User-edited sparse or contradictory fact graphs: missing edges must not silently become facts.
- Empty/oversized queries and invalid relation/object names: reject or halt consistently.
- Snapshot from another episode or invalid JSON checkpoint: reject without damaging live state.
- Repeated packet deletion or cycles: stop at a bounded cycle cap and mark unfinished work.
- Concurrent HTTP clients: sessions must not accidentally share mutable agent state.
